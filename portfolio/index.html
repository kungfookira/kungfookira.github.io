Siarix

Make autonomous systems understandable and governable.

Design challenge. Operators need to understand AI decisions, permissions and workspace boundaries without navigating raw infrastructure.

Interface approach. Separate public product education from operational interfaces. Organize workspace governance, quality reviews, prediction feedback and administrative controls into dedicated views.

  1. Understand
  2. Configure
  3. Review
  4. Govern
Read UX case study

Interaction rationale & tradeoffs

The operator must distinguish a proposed action from an approved or completed action. Navigation separates Mission Control, Executions, Decision Firewall, Agents & Authority, Evidence & Beliefs, Cognitive Ledger and Workspace Access. Capacity controls explicitly distinguish inference allocations from invoice caps; errors are surfaced in the form. A useful evaluation would test whether an operator can locate a policy violation and explain why it occurred without consulting raw logs.

Representative task

Find the relevant execution → inspect evaluation → review authority and evidence → choose a permitted next action.

Proposed usability evaluation

Task completion, time to identify a blocked action, comprehension of capacity limits.

Evaluation criteria are proposed, not measured outcomes.

02 / Privacy / Browser extensionDevelopment prototype

NullaKey

Put identity consent at the point of action.

Design challenge. A user needs to know which website is requesting a passport, what is being authorized and whether payment or evidence is required.

Interface approach. Use an origin-specific approval queue, explicit agent permissions, separate checkout, revocation controls and clear connection and proof status. Distinguish human approval from delegated agent approval.

  1. Connect
  2. Review origin
  3. Approve
  4. Verify
Read UX case study

Interaction rationale & tradeoffs

Two distinct audiences need different flows: individuals approving a site-specific passport and merchants setting up verification. The extension exposes origin, consent, revocation and proof state; the merchant portal sequences domain proof, subscription and installation. Credentials are shown once with explicit clear/copy actions. The tradeoff is information density versus disclosure of consequential permissions.

Representative task

Connect browser key → inspect origin and permissions → approve or revoke; merchant: prove domain → subscribe → install.

Proposed usability evaluation

Consent comprehension, correct origin selection, merchant setup completion, recovery from unavailable verification.

Evaluation criteria are proposed, not measured outcomes.

03 / Developer tools / UtilityProduct implementation

01Convert

Reduce friction in everyday data transformations.

Design challenge. Switching between individual converter tools interrupts technical workflows and creates unnecessary steps.

Interface approach. Unify formats in one workspace, support file import, automatic detection and reusable recipes; make optional cloud snippets distinct from local conversion.

  1. Import
  2. Detect
  3. Convert
  4. Copy
Read UX case study

Interaction rationale & tradeoffs

The workspace groups common transformations around input and output rather than separate pages for each format. File import, an example, clear, copy, download and reuse-output controls support repeated tasks. Recipe steps allow repeatable workflows, with optional cloud storage distinct from local use. The design challenge is balancing discoverability with a compact workspace.

Representative task

Paste or import → select transform → inspect result → copy/download or reuse.

Proposed usability evaluation

Time to first valid output, successful repeated transformation, error recovery, understanding local versus cloud storage.

Evaluation criteria are proposed, not measured outcomes.

Quantomworm

Give complex operations a single visual hierarchy.

Design challenge. Multiple metrics and activity streams compete for attention in a dense monitoring interface.

Interface approach. Place summary metrics first, then a chart and activity feed, followed by modular control panels. Responsive grids adapt the density to viewport width.

  1. Scan metrics
  2. Inspect trends
  3. Review activity
  4. Open controls
Read UX case study

Interaction rationale & tradeoffs

A responsive metric-card row establishes overview hierarchy, then a chart and activity feed provide context, followed by modular panels. The source includes hard-coded example values; these are not real performance outcomes. A useful redesign would prioritize actionable alerts over decorative density.

Representative task

Scan overview → inspect chart → review activity → select relevant module.

Proposed usability evaluation

Time to find a metric, accuracy interpreting trend, mobile readability.

Evaluation criteria are proposed, not measured outcomes.

Business Funding Research

Make financing comparisons evidence-led.

Design challenge. Business owners need to compare financing terms without mistaking promotional claims for verified facts.

Interface approach. Group guides by financing category and market; surface methodology, evidence requirements, limitations and compensation disclosures alongside exploration paths.

  1. Choose category
  2. Explore guide
  3. Check evidence
  4. Compare options
Read UX case study

Interaction rationale & tradeoffs

The homepage groups guides by category and market, provides a situation-based research path and exposes methodology and referral disclosures. The interface separates research from third-party provider options. Evidence limits are part of the experience, not merely footer text.

Representative task

Select category or situation → read guide → examine evidence → compare terms.

Proposed usability evaluation

Findability of a relevant guide, comprehension of disclosures, ability to compare terms.

Evaluation criteria are proposed, not measured outcomes.

Elm & Key Properties

Bring property discovery and booking into one experience.

Design challenge. Guests need to review accommodation information and understand the booking path without excessive navigation.

Interface approach. Use a responsive two-column layout combining property presentation and booking information, with a single-column layout on smaller screens.

  1. Explore property
  2. Check availability
  3. Review booking
  4. Continue to payment
Read UX case study

Interaction rationale & tradeoffs

The property page uses a responsive two-column layout for presentation and booking information, collapsing to one column on narrow screens. The design intent is to keep decision context near the booking path; payment and availability need independent end-to-end verification.

Representative task

Review property → inspect availability → review booking information → continue to payment.

Proposed usability evaluation

Mobile task completion, clarity of booking requirements, payment handoff comprehension.

Evaluation criteria are proposed, not measured outcomes.

Findability, distinction between documented and unverified claims, navigation efficiency.
